Audio sources

Rights. You are responsible for the rights to every song you display and every audio file you attach and play. These pills do not use a real recording. They play fixtures/audio/test-tone.wav, a short tone generated by scripts/generate-fixtures.mjs, and they link to a placeholder track id that is not a Spotify song.

Run npm run build && npm run serve and open http://127.0.0.1:4391/examples/sources/. Autoplay is off, so use each pill's sound button. With autoplay left at its default, a blocked browser starts sound on the next click or key press.

One file

Bottom left. audio-src points at the generated WAV. The type is inferred from the extension.

<music-pill audio-src="/audio/licensed-song.wav" …></music-pill>

Several files

Bottom right. The first <source> has a type no browser plays, so it is skipped and not fetched. The WAV is the one that plays. A real page would list MP3, M4A/AAC, OGG, and WAV of the same recording.

<music-pill …>
  <source src="/audio/licensed-song.mp3" type="audio/mpeg">
  <source src="/audio/licensed-song.ogg" type="audio/ogg">
  <source src="/audio/licensed-song.wav" type="audio/wav">
</music-pill>

Nothing can play

Top right. The only source declares a type the browser rejects, so the pill shows an error and does not fetch the file. The Spotify link still only opens Spotify.
